## 先写内容，再调整形式

Markdown 让你用纯文本完成大多数常见排版。文章跟代码放在同一个项目里，可以回顾修改，也方便迁移。

在这个博客中，文章保存在 `src/content/blog/` 目录。新增一个 `.md` 文件，就能开始写作。

## 为文章填写基本信息

每篇文章的顶部都有一段用三个短横线包围的元信息：

```yaml
---
title: "我的第一篇文章"
description: "用一句话说明这篇文章在讨论什么。"
pubDate: 2026-10-30
tags: ["日常实践"]
draft: false
sample: false
---
```

标题、摘要和发布日期必填。标签用于自动生成主题页面；`draft: true` 表示草稿，不会生成公开文章页面，也不会出现在列表、标签和 RSS 中。

### 选择一个稳定的文件名

比如 `my-first-post.md`，对应文章地址是 `/blog/my-first-post/`。发布以后尽量保持文件名不变，避免旧链接失效。

## 常用排版示例

正文从二级标题开始，文章标题由页面自动呈现。二级和三级标题会进入右侧的文章目录。

你可以使用 **加粗** 表达重点，也可以用 *斜体* 标注词语。行内代码像这样：`npm run dev`。

### 列表和引用

1. 写下一个具体的问题。
2. 补充过程和例子。
3. 检查结论是否有证据。

> 清楚的表达，通常来自对问题本身更清楚的理解。

### 代码块

在代码块开头注明语言，页面就会显示对应的代码高亮。

```typescript
const ideas = ['观察', '记录', '实践'];

for (const idea of ideas) {
  console.log(idea);
}
```

### 表格

| 字段 | 用途 | 是否必填 |
| --- | --- | --- |
| title | 文章标题 | 是 |
| description | 文章摘要 | 是 |
| pubDate | 发布日期 | 是 |
| tags | 文章标签 | 否 |
| draft | 是否为草稿，默认 false | 否 |
| featured | 是否首页精选，默认 false | 否 |

## 写完以后怎么检查

运行 `npm run dev` 查看页面。提交之前，运行 `npm run check` 和 `npm run build`，检查类型、文章字段和静态页面生成是否正常。

写作最好的开始方式，往往就是先完成一个不太长的段落。
