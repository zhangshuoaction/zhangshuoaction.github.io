## 先确认最重要的那条路径

一个博客最基本的价值，是让作者发布内容，让读者顺利阅读。

因此，第一版可以围绕一条完整路径展开：

**新增文章 → 本地预览 → 构建静态页面 → 发布 → 读者访问。**

当这条路径可靠以后，再考虑搜索、评论和更多个性化功能。

## 静态内容如何变成网页

在这个项目中，Markdown 保存正文，Astro 组件负责页面结构，CSS 负责视觉样式。构建时，工具把它们组合成可以直接访问的 HTML 和静态资源。

读者打开页面时，首先得到的是文章本身。大多数阅读行为不需要额外的交互脚本。

### 内容结构保持简单

文章放在一个目录里；公共页头、页脚和元信息由布局统一提供；标签从文章数据自动汇总。

这样，发布一篇文章只需要添加一个文件，而不必同时修改多个导航或列表页面。

## 第一版要检查什么

```bash
npm run check
npm run build
npm run preview
```

构建成功之后，还需要检查实际页面：

- 手机宽度下，标题、正文和代码块能否阅读。
- 文章链接、标签链接和目录锚点是否有效。
- 草稿是否确实从公开页面中排除。
- RSS 和 Sitemap 中的地址是否符合最终部署地址。

## 把后续变化留给真实需要

如果文章多到难以查找，再加入搜索。如果有了持续交流的需要，再选择评论服务。

保持一个小而完整的起点，让维护成本与实际需要一起增长。
